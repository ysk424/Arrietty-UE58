## 本日の合意

- B案を採用する。世界制作は別のUEプロジェクトで行い、Arriettyの運動・飛行機能と分離する。
- Arrietty専用エクスポーターは、制作元UEプロジェクトへ入れるEditor用プラグインとする。
- 利用者がUEエディターで制作物を完成・保存し、エクスポーターから明示的に書き出す。
  書き出しは利用者の責任であり、Arriettyの通常起動時に自動で再エクスポートしない。
- 元のプロジェクトは通常 `Documents/Unreal Projects/<プロジェクト名>` に置く。
  出力は別の `Documents/Arrietty Projects/<プロジェクト名>` に置く。
  Unreal Projects直下に準備用・出力用の別プロジェクトを増やさない。
- 出力ディレクトリには固定名 `world.json` と必要な変換済みファイルを保存する。
  `Documents` はWindowsの実際のドキュメントフォルダーを解決する。
- JSONを受け渡しの入口とし、元の `.uproject` のフルパス、対象マップ、元データと
  変換データの整合性情報、対応する実行環境、出発地点などを記録する。
- インポーター／準備処理は必要に応じて元プロジェクトと出力側の両方を参照する。
  制作プロジェクトを丸ごと複製せず、実行に不要な大容量ファイルは制作側に残す。
  元参照か変換かはUEの実行・Cook・依存関係の要件から決める。
  未CookのUEアセットを、パスが分かるだけでパッケージ実行から読めるとは扱わない。
- 書き出し後に対応する元データが変わった、欠落した、変換済みデータと不一致になった場合は
  明示的なエラーとし、利用者へ再保存・再書き出しを案内する。
  古い版への自動フォールバックや、最新データへの黙った置き換えはしない。
- 制作専用エクステンションはArrietty実行側に持ち込まない。
  実行時依存を除去／変換できないものは理由を示して書き出しエラーにする。
- 起動は「実行状態の初期化 → 世界の検証・準備 → シミュレーター実行」の順とする。
  世界の準備と起動を一つのランチャーが管理してよい。
- 本体と確認済みの元データを毎回上書きせず、セッション状態を初期化する。
  機器設定と運動記録は保持する。本体の機能更新を古いバックアップで巻き戻さない。
- 世界準備の必要があれば、ゲーム起動前にUEのバッチ処理を実行して終了してよい。
  ゲーム中はUEエディターを必要としないWindows実行版を目標とする。
  ここでいうエディター不要はVR描画を伴う実行であり、NullRHIによる無描画とは異なる。
- 世界の追加・更新でArrietty本体やUEのEngineディレクトリを書き換えない。
  対応範囲内の世界追加だけではArrietty本体の再ビルドを必要としない。
- 起動前に整合性・対応機能を検査する。新しい世界の失敗で本体を壊さない。
  起動前検査が全実機動作を保証するとは主張しない。

## 現在の操作仕様を保持

追跡切れ停止、機器停止・ログ保存の扱いも保持する。
ユーザーが昨日のフィットネスを良好と報告したことと、自動試験・個別機器測定は区別する。

### 実装結果と再開情報（2026-09-08）

エクスポーター、検証・起動処理、エディター不要のWindows実行版を実装した。
使い方は [WORLDS.md](WORLDS.md)、確認結果と実機で残る範囲は [VALIDATION.md](VALIDATION.md)。

- 作業cwdは必ず `C:/Users/azoo/git/Arrietty-UE58-worlds` を指定する。既定cwdは元チェックアウトなので注意。
- 固定JSON形式は `arrietty.world` version 1、実行ABIは `ue58-worlds-1`。
  `arrietty_ue/worlds.py` が元Content/Config/Source等のSHA-256、出力pak、版・出発点を検証する。
  元データの追加・削除も不一致。元参照は読み取り・照合だけに使用する。
- `exporter/` はEditorのToolsメニューから保存済みマップを書き出すPythonプラグイン。
  `tools/install_world_exporter.py <source.uproject>` で指定した制作元へ配置する。
  同日の追加依頼で `install-world-exporter.ps1 <フォルダー名>` を追加した。
  ユーザープロファイルの `Documents/Unreal Projects` 直下から制作元を見つける簡易入口。
  インストール先の `.uproject` は初回バックアップを作る。
  今回インストールしたのはworktree内の試験プロジェクトだけ。既存の制作物は未変更。
- 必要な保存済み依存パッケージだけを出力側の `.work-<id>/ArriettyUE` に一時収集し、
  UEのCookとUnrealPakでWindows用 `.pak` を生成する。IoStoreと共有マテリアルシェーダーは使用しない。
  同一のUEビルド・描画設定でCookし、元のUEパッケージパスを保持する。
  制作用プラグインのバイナリはコピーしない。本体にない実行コード依存はエラー。
  変換成功後だけworld.jsonを原子的に公開し、一時入力コピーを削除する。
- `ArriettyGameInstance` が最初のゲームマップ読み込み前に外部pakをmountする。
  外部マップでもArriettyGameModeを使用し、PlayerStartの位置・yawを出発点として渡す。
  外部世界の光源・空・ポストプロセスは制作時の設定を保持し、Tuvalu専用日時UIは隠す。
  Button 1・R・操舵・追跡切れ停止の既存処理を保持する。
- `tools/package_runtime.ps1` でWindows Development実行版を作成済み。
  `build/runtime/Windows` と `arrietty-runtime.json` が結果。本体機能更新時に再生成する。
  対応範囲内の世界変更だけなら、本体再ビルドは不要。
- `start.ps1 -WorldManifest <world.json>` が入口。`start-ue.ps1` からも同じ引数を受け付ける。
  `tools/start_world.py` は本体と世界を先に検証し、検証成功後に新しいセッションを作って実行する。
  `.runtime/world-sessions/<id>` に設定・状態・CSV・ログ・画面保存を分離する。
  本体のファイルをバックアップで巻き戻す必要はなく、前回のゲーム保存も読み継がない。
  新経路の既定UDPは19859、試験は29859。旧経路の試験は29858。
- 世界は出力フォルダー内のpakから直接読むため、ArriettyのContent/Engineへ世界は蓄積しない。
  世界の過去pak、失敗時の作業ディレクトリ、セッション記録のディスク使用量は別途増える。
  現world.jsonが参照しない過去pakと失敗時の作業場所は、実行していないときに削除可能。
  運動記録の自動削除はしない。
